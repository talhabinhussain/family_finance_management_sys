# 08 — Settings (Appearance: Light / Dark mode)

Read `00_frontend_overview.md` and `frontend_design_theme.md` first. Follow the patterns of `02_expenses.md` to `07b dashboard.md`.

## 1. Goal and scope

Build the `/settings` page with **one section only: Appearance**. The user picks **Light** or **Dark**. The choice applies to the whole app instantly and survives a page refresh.

Rules:

- **Frontend only.** No backend change, no new endpoint, no table, no `api.ts` call, no SQL. The theme is a per-device UI preference stored by `next-themes` in `localStorage`. The backend has no users or auth, so there is nothing to attach a stored preference to.
- **`next-themes` is already installed** (`^0.4.6`) and `components/ui/sonner.tsx` already calls `useTheme()`. Do not add another theme library.
- **shadcn first.** Use existing `Card`, `Label`, `Skeleton`. Add only `radio-group` through the shadcn CLI. Never hand-edit files in `components/ui/`.
- **Default theme is Light.** This keeps the current look unchanged for anyone who never opens Settings.
- Do not use `dark:` utility classes in feature components. Colors come from tokens in `globals.css`, so changing the `.dark` token block restyles every page.

Out of scope: "System" option, header toggle button, accent colors, font size, language or currency settings, Members/Accounts/Categories/Income Sources tabs, per-user preferences, saving the theme to the database, theme animations or transitions.

## 4. Wiring the theme provider

`app/providers.tsx` — `ThemeProvider` is the outermost wrapper so `Toaster` (inside) can read the theme:

```tsx
import { ThemeProvider } from "next-themes";

return (
  <ThemeProvider
    attribute="class"
    defaultTheme="light"
    enableSystem={false}
    disableTransitionOnChange
  >
    <QueryClientProvider client={queryClient}>
      {children}
      <Toaster richColors />
    </QueryClientProvider>
  </ThemeProvider>
);
```

Keep the existing `QueryClient` setup unchanged.

`app/layout.tsx` — add one prop. `next-themes` sets the `class` on `<html>` before React hydrates, so React must not warn about it:

```tsx
<html lang="en" suppressHydrationWarning className={`${geistSans.variable} ${geistMono.variable} h-full antialiased`}>
```

How it works (viva): `next-themes` injects a tiny inline script that reads `localStorage["theme"]` and adds or removes the `dark` class on `<html>` before first paint. Tailwind's `dark` variant and the `.dark { ... }` CSS variables then take over. `setTheme("dark")` updates the class and writes `localStorage`.

## 6. Hook: `hooks/use-mounted.ts`

On the server `useTheme()` has no value, so rendering the selected radio from it causes a hydration mismatch. This hook returns `false` on the server and during hydration, then `true`. It is lint-safe (no `setState` inside `useEffect`).

```ts
import { useSyncExternalStore } from "react";

const subscribe = () => () => {};

export function useMounted() {
  return useSyncExternalStore(
    subscribe,
    () => true,
    () => false,
  );
}
```

## 7. UI requirements

### 7.1 Page

`app/(dashboard)/settings/page.tsx` is a server component that renders only `<SettingsView />`, like the other pages.

`SettingsView` (client): `<PageHeader title="Settings" description="Manage how the app looks on this device." />`, then `<AppearanceCard />`. Use the same page spacing as the other views (the dashboard shell already provides `max-w-6xl` and `gap-6`).

### 7.2 `AppearanceCard`

shadcn `Card` with:

- `CardTitle`: "Appearance"
- `CardDescription`: "Choose the theme used across the app. Your choice is saved on this device."
- `CardContent`: a shadcn `RadioGroup` with two option tiles in a two-column grid (`grid gap-3 sm:grid-cols-2`).

Each tile is a `Label` (`htmlFor` matches the item `id`) containing: a lucide icon (`Sun` for Light, `Moon` for Dark), the option name, a one-line description, and the `RadioGroupItem`. The selected tile gets `border-primary bg-accent`; others get `border-border`. Tiles must be keyboard operable (arrow keys move between options, as the radio group provides) and show a visible focus ring.

Reference implementation (adjust prop details to the generated `radio-group.tsx`; do not edit that file):

```tsx
"use client";

import { Moon, Sun } from "lucide-react";
import { useTheme } from "next-themes";
import {
  Card,
  CardContent,
  CardDescription,
  CardHeader,
  CardTitle,
} from "@/components/ui/card";
import { Label } from "@/components/ui/label";
import { RadioGroup, RadioGroupItem } from "@/components/ui/radio-group";
import { Skeleton } from "@/components/ui/skeleton";
import { useMounted } from "@/hooks/use-mounted";
import { cn } from "@/lib/utils";

const options = [
  {
    value: "light",
    label: "Light",
    description: "Bright background, easy in daylight.",
    icon: Sun,
  },
  {
    value: "dark",
    label: "Dark",
    description: "Dim background, easier on the eyes at night.",
    icon: Moon,
  },
] as const;

type ThemeChoice = (typeof options)[number]["value"];

export function AppearanceCard() {
  const { theme, setTheme } = useTheme();
  const mounted = useMounted();
  const current: ThemeChoice = theme === "dark" ? "dark" : "light";

  return (
    <Card>
      <CardHeader>
        <CardTitle>Appearance</CardTitle>
        <CardDescription>
          Choose the theme used across the app. Your choice is saved on this
          device.
        </CardDescription>
      </CardHeader>
      <CardContent>
        {!mounted ? (
          <div className="grid gap-3 sm:grid-cols-2">
            <Skeleton className="h-20 w-full" />
            <Skeleton className="h-20 w-full" />
          </div>
        ) : (
          <RadioGroup
            value={current}
            onValueChange={(value) => setTheme(value as ThemeChoice)}
            aria-label="Theme"
            className="grid gap-3 sm:grid-cols-2"
          >
            {options.map(({ value, label, description, icon: Icon }) => (
              <Label
                key={value}
                htmlFor={`theme-${value}`}
                className={cn(
                  "flex cursor-pointer items-start gap-3 rounded-lg border p-4",
                  current === value
                    ? "border-primary bg-accent"
                    : "border-border",
                )}
              >
                <RadioGroupItem id={`theme-${value}`} value={value} />
                <span className="flex flex-col gap-1">
                  <span className="flex items-center gap-2 text-sm font-medium">
                    <Icon className="size-4" aria-hidden="true" />
                    {label}
                  </span>
                  <span className="text-[13px] font-normal text-muted-foreground">
                    {description}
                  </span>
                </span>
              </Label>
            ))}
          </RadioGroup>
        )}
      </CardContent>
    </Card>
  );
}
```

States: loading is the `Skeleton` pair before mount. There is no empty or error state (no data fetch). **No sonner toast**: a theme change is not a data mutation and the UI changes immediately.

## 8. Acceptance and verification

Run from `/frontend`: `npm run lint` and `npm run build` must pass with no new warnings.

Manual checks (do each in both themes):

1. `/settings` opens from the sidebar; Light is selected on a fresh browser profile.
2. Selecting Dark changes the whole app at once, with no reload. Selecting Light restores the original look exactly.
3. Refresh the page: the choice persists and there is no visible flash of the wrong theme.
4. Open every page (Dashboard, Expenses, Income, Bills, Savings, Budgets, Reports, Settings). No white boxes, unreadable text or invisible borders.
5. Reports: the income bars (green) and expense bars (red) are clearly different; axis labels and tooltips are readable.
6. Open one dialog, one select dropdown and trigger one toast (for example, add an expense). All follow the theme.
7. Income amounts show green, expense amounts show red, warning/over-budget badges are readable on the budgets and dashboard pages.
8. Mobile width: the sidebar sheet and the Settings tiles look correct; tiles stack to one column.
9. Keyboard: Tab reaches the radio group, arrow keys switch the theme, focus ring is visible.
10. DevTools: no hydration warning in the console on `/settings`.

Done when all checks pass, only the files in §3 changed, and `components/ui/` contains no hand edits (only the generated `radio-group.tsx` is new).

## 9. Risks

| Risk                                         | Prevention                                                                      |
| -------------------------------------------- | ------------------------------------------------------------------------------- |
| Hydration warning on the radio group         | Use `useMounted()` and render the `Skeleton` until mounted                      |
| Flash of wrong theme on first paint          | `suppressHydrationWarning` on `<html>`; provider uses `attribute="class"`       |
| Dark mode does nothing                       | Provider must use `attribute="class"` to match `@custom-variant dark`           |
| Chart bars look the same in dark             | Replace the `.dark` block as given in §5, including `--chart-1` and `--chart-2` |
| Agent adds `dark:` classes across components | Forbidden by §1; fix tokens instead                                             |
| Scope creep (System option, header toggle)   | Listed as out of scope in §1                                                    |
